# 架构与边界

## 分层规则

Domain 仅使用 Python 标准库。Application 只导入 Domain 和自身模块，不能依赖 FastAPI、AgentScope、SQLAlchemy、Redis。Infrastructure 实现领域端口；Presentation 将 HTTP/WS 请求转为应用调用；composition 负责把具体实现装配起来。

AgentScope 是基础设施框架：如果把 `Agent`、`FunctionTool` 直接导入 Application，就违反了“Application 只依赖 Domain”的要求。因此 `application/agents/` 保留职责和工具范围，具体 AgentScope 对象创建在 `infrastructure/agentscope_runtime.py`。这是有意的依赖倒置，不是空壳替代：LLM 模式运行的是实际 AgentScope Agent 循环。

## Agent 与工具

| Agent | 能力 | 限制 |
|---|---|---|
| CommerceConcierge | 所有业务工具、Task 四件套、task_dispatch、偏好提案 | 不能确认提案，不接受 buyer_id |
| CatalogSearchAgent | 商品检索、知识检索、网页检索 | 无交易工具，不再派发 |
| OrderTradeAgent | 购物车、报价、订单查询、取消提案 | 交易串行，实际写入需用户确认 |

优先主 Agent 单干。只有 parallel / isolation / deep_chain（三步及以上）才允许派发。服务端校验枚举、深度、数量、角色；判断是否“值得隔离”本身仍由模型做语义判断。最多三项任务，多个子任务只允许搜索角色；递归派发被工具白名单阻止。

## 事务、确认与身份

- 游客入口生成随机 bearer token，SQLite 仅存 token 的 SHA256；有效期30天。买家 ID 从凭证解析，前端和模型均不能传入任意 buyer_id。
- 这是本地学习用途的游客身份，不是完整企业账户系统。清空浏览器凭证后原购物数据仍在数据库，但没有登录找回能力。
- 订单、偏好和取消操作先生成15分钟有效的提案；模型没有确认工具。用户通过鉴权 REST 接口确认。
- 下单重新检查购物车 revision、商品价格、库存。购物车任何变化会使旧报价失效。
- SQLite `BEGIN IMMEDIATE` + WAL 串行化写事务，订单写入、库存扣减、购物车清空、确认状态、幂等结果、审计事件一起提交。
- 相同买家/幂等键/参数重试返回之前结果；同键不同参数拒绝。取消重复执行不会多次返还库存。
- 查询工具无副作用，但每次读取最新数据，避免同一轮先读购物车、再改购物车、再读时返回旧值。业务写工具按 job+tool+args 生成稳定键。
- TaskCreate/Update 包装内置工具，以结果+计划快照持久化，重投任务不重复创建计划；Get/List 保持实时。
- 每个买家的订单、偏好、确认项、会话均在 SQLite 查询中强制带 owner。库存为所有买家共享。

## 队列与事件

REST 提交任务 → SQLite jobs/outbox + user_message → Redis Stream 通知 → worker claim → Agent 执行 → SQLite 会话状态/最终消息 → Redis Pub/Sub 通知。

Redis Streams consumer group 提供队列与待处理消息回收；SQLite 中待执行任务是最终依据，所以 Redis 不可用也能通过扫描恢复。任务有60秒租约、15秒心跳，过期后重领；业务事务提交前检查 worker fence，旧 worker 不可继续提交。每个会话 FIFO，不同会话可由多个 worker 并行；最多三次恢复后标为失败。worker 超时/宕机重试属于至少一次执行，不保证 LLM 请求本身只调用一次；业务副作用由持久化幂等和 fence 约束。

事件表有自增 seq。WebSocket 首帧鉴权，以 seq 重放恢复；Redis Pub/Sub 加速唤醒，SQLite 轮询补齐缺口。前端连接断开时重连并使用 REST 补拉。事件仅包含公开回复、工具和使用量，不向 UI 暴露模型隐藏思维链。

会话状态只在一轮成功结束后保存。中断轮次由最后成功状态重跑；已有工具写入按幂等键恢复。业务确认是前端独立操作，模型失败不回滚用户已确认订单。

## 检索与缓存

商品检索：模型在调用工具前消解指代/扩展查询；服务端补充中英文别名 → OpenAI兼容 embedding → Qdrant top20 → 可选 HTTP rerank → topK。

降级链：embedding+rerank → embedding_only → keyword_2gram。没有商品命中且属于政策/关税问题时尝试 web_search；SearchAgent 也可主动调用知识库与网页工具。

Redis embedding缓存按 endpoint/model/text 隔离；语义缓存仅记录候选商品 ID，余弦阈值0.997、最多50条、TTL120秒，按模型和目录内容版本隔离。商品价格和库存始终从 SQLite 重新补齐；不缓存个人对话、偏好、订单或最终 LLM 回复。重排每次执行，避免把近似查询的排序误用。

知识库是实际 `agentscope.rag.KnowledgeBase`，Markdown → TextParser → ApproxTokenChunker → OpenAIEmbeddingModel → QdrantStore。与商品集合分离。未配置时明确走本地关键词读取。批量索引时先删除同文档旧片段再写新片段，避免短文档留下旧尾部；索引期间该文档可短暂不可见，失败需重新执行索引。

## ContextConfig 与 Cache Breakpoint

system prompt 按文件读取，不插入当前时间、偏好、订单或摘要；动态购物状态追加在用户消息中。关闭 SDK runtime injection 保持 system 前缀稳定，工具注册顺序固定。前缀稳定是缓存优化条件，不承诺任一 provider 的命中率。OpenAI兼容协议不存在统一的显式 cache breakpoint 参数，本工程不虚构该参数；供应商特定缓存标记需另外适配。

`ContextConfig(trigger_ratio=.7, reserve_ratio=.15, tool_result_limit=6000)` 控制压缩。要求模型摘要不超过350 tokens，压缩后 middleware 再硬裁到500 UTF-8字节；对于 byte-BPE tokenizer，这是不超过500 tokens的保守上界。此限制比500个中文字符严格。完整消息、订单、偏好、计划仍在数据库/AgentState中，不依赖摘要保存业务事实。第三方非 byte-BPE 分词器需替换为该模型官方 tokenizer。

## 适用范围

这是完整的可运行学习工程，包含健壮性措施，但不是直接处理真实支付的生产电商系统。未实现真实税务、支付、地址、物流、商品供应商同步、账户登录找回、多租户组织、运维监控与数据库迁移。SQLite 数据表使用显式表名+JSON聚合内容，便于阅读；大规模生产应迁移到具备行锁的数据库并引入 schema migrations。只应在单机共享本地卷运行 SQLite，不能把卷放到不可靠的网络文件系统。

API/前端端口默认仅绑定宿主机 localhost。发布到互联网之前需要正式认证、TLS、配额/限流、密钥托管、审计与数据保留策略。不会因缺少密钥而悄悄切换模式：LLM模式缺密钥会明确启动失败。
